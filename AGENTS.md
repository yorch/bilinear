# Project Guidelines

This file provides guidance to AI Agents when working with code in this repository.

## Project Overview

A Linear-style issue tracker built with Next.js 16 (App Router), Apollo Server GraphQL, Prisma 7, PostgreSQL, MobX, and real-time sync via WebSocket + Redis Pub/Sub. Offline-first with Dexie.js (IndexedDB) client cache.

### Recently shipped (2026-07-15, whole-repo code review — security, authz, sync, data)

- **Multi-dimension review of the whole codebase (8 angles), then a fix → code-review → simplify pass.** Every finding below was verified against the source before fixing; all fixes carry unit tests where a test surface exists, and the full gate suite (`yarn lint`, `yarn typecheck`, `yarn test`, `yarn lint:tokens`, `yarn build`) is green. Several changes are **security-sensitive** — a real-browser / staging pass before merge is still recommended (this environment has no Docker daemon or live DB, so runtime auth/SSO flows were verified by tests + reasoning, not exercised end to end).
- **Critical: Prisma client was rebuilt on every query in production** (`src/server/lib/prisma.ts`). `getLazyClient()` only memoized the client when `NODE_ENV !== 'production'`, and the exported `prisma` Proxy calls it on every property access — so production opened a fresh `PrismaClient` + `pg.Pool` per query → connection exhaustion. Now memoized in all environments.
- **The intra-org team/guest boundary was the weak axis.** The top-level `issues` query enforced guest/team visibility, but sibling issue-returning surfaces re-implemented or skipped it. Closed on `searchIssues`, `Team.issues`, `issue(id)`, `comments`, `Issue.parent`/`children`, `organizationExport` (now org-admin only), the `/api/sync/bootstrap` + `/api/sync/delta` endpoints (guests no longer download the whole org — see the new shared `buildGuestVisibilityWhere` in `src/server/lib/issue-visibility.ts`), and the Yjs collab server (now checks team membership + guest status, not just org). The six non-GraphQL routes now resolve auth through `extractAuthContext` (via the new `requireAuthContext` helper in `middleware/auth.ts`) so org suspension / user deactivation is enforced, not just trusted from the JWT.
- **SSO hardening** (`saml.service.ts`): validate assertion `Conditions` (`NotBefore` optional, `NotOnOrAfter` required), `AudienceRestriction`, and `SubjectConfirmation`; a replay guard keyed on assertion id (cached for the full clock-skew window); and a fail-closed signature verifier (no whole-document fallback, digest required, single-assertion check). Still hand-rolled — a vetted XML-DSig library (`xml-crypto`/`@node-saml/node-saml`) and a Redis-backed replay store remain the recommended follow-ups.
- **Cross-org write injection** closed: `issueCreate`/`issueUpdate`/`issuesBulkUpdate` now validate `parentId`/`projectId`/`cycleId`/`projectMilestoneId`/`assigneeId`/`labelIds` belong to the issue's org (and team where applicable) via `IssueService.validateReferences`. `issuesBulkUpdate` now stamps lifecycle timestamps like the single-update path; issue-list pagination has a stable `(sortOrder, id)` order and a correct `hasNextPage`.
- **GitHub PR-merge auto-close** now routes through `IssueService.update` so it emits SyncActions (clients actually receive the close), runs the parent/child cascade, and dispatches the `issue.updated` webhook — closes concurrently across issues.
- **Other correctness:** cycle auto-rollover picks the contiguous next cycle (`endsAt > now`); initiative progress is computed from live `ProjectService.getProgress` instead of the never-written `Project.progress` column; the `'cancelled'`→`'canceled'` analytics typo (canceled issues were counted as open) is fixed; cross-org favorite writes are blocked and same-org double-favorite is idempotent again; the `@mention` fan-out only notifies users with access to the issue's team (was an unauthenticated disclosure/spam vector); the activity timeline's broken `avatarBgColor` selection is aliased to the real field.
- **Client sync:** offline mutations now pause instead of being dropped after a retry budget (a reachable-server 5xx/429 still bounds out so it can't block the FIFO forever); delta pagination uses a local cursor so a concurrent live WS apply can't skip the backlog; a post-connect follow-up delta closes the watermark/subscribe gap.
- **GraphQL hardening:** `formatError` masks internal errors while passing through the documented client-error codes (incl. `OAUTH_ERROR`); list `limit` args are clamped (shared `clampLimit` in `src/server/lib/pagination.ts`); the `DateTime` scalar rejects unparseable input.
- **Tooling:** the design-token ratchet's `--update` now refuses to grow the baseline (was gameable); Dependabot gained the npm ecosystem; `.env.example` documents the previously-missing security vars (`GRAPHQL_ALLOWED_ORIGINS`, `ALLOW_PRIVATE_WEBHOOK_URLS`, `AUTH_RATE_LIMIT_FAIL_CLOSED`, upload/WS/YJS/Slack config).
- **Known residuals (deliberately not fixed this round):** the delta commit-watermark is still an app-server-clock heuristic vs Postgres `statement_timestamp()` (a robust fix needs commit-ordered reads / xmin fencing); several DB-level items need migrations a live DB can't be verified against here (favorite unique key should include `organizationId`; missing FKs on `File.uploaderId`/`Webhook.teamId`/`SlackIntegration.defaultTeamId`; partial soft-delete indexes; `sync_actions` retention); the initiative rollup still issues per-project `getProgress` queries; and `useIssueUpdate` was left store-coupled (the standalone issue route reconciles local state itself).

### Recently shipped (2026-07-10, design-token debt: literal zero)

- **The last 15 raw-color occurrences — `tiptap-editor.tsx`'s `CURSOR_COLORS` and `issue-utils.ts`'s `PRIORITY_CONFIG` — turned out convertible too**, closing the ratchet baseline to a literal empty `{}`. Both were previously accepted as "N legitimately distinct values, not a semantic role" and left as hex literals; that's still true of the *palette design*, but it doesn't mean the values have to live as raw hex in `.ts`/`.tsx` source. Moved both behind CSS custom properties in `globals.css` (`--priority-none/urgent/high/medium/low`, `--cursor-1` through `--cursor-10`, literal hex values preserved exactly — no oklch round-trip, zero visual change), referenced via `'var(--priority-x)'`/`'var(--cursor-n)'` strings instead of raw `#rrggbb`.
  - `PRIORITY_CONFIG`'s colors are consumed exclusively via React inline style (`style={{ color: config.color }}` in `priority-icon.tsx`, `style={{ backgroundColor: cfg.color }}` in `sub-issue-list.tsx`/`bulk-action-bar.tsx`/`issue-context-menu.tsx`) — a `var()` string works identically to a literal hex there, no risk.
  - `CURSOR_COLORS` looked riskier at first glance: the color is stamped into a Yjs/Hocuspocus **awareness** field (`provider.setAwarenessField('user', { color, name })`) and synced across the network to every other connected peer's browser, where the TipTap `CollaborationCursor` extension renders it as a remote cursor's decoration color. Checked the extension config (`CollaborationCursor.configure({ provider })`, no custom render/color function) — it just assigns the string to a CSS property, doing no programmatic color math (darkening, contrast calculation, etc.) on it. Since every peer loads the identical `globals.css`, a `var(--cursor-n)` reference resolves to the same color on every client — safe to convert.
  - Neither token family is registered in `@theme inline` (they're not Tailwind utility classes — nothing does `bg-priority-urgent` or `text-cursor-3` in markup — only consumed via inline style / awareness payload), and neither needs a `.dark` override (both palettes render identically in both themes today, same as before the conversion — preserving that, not introducing new adaptive behavior).

## Architecture

### Request Flow

```
Client (MobX stores) → GraphQL mutation via fetch (no Apollo Client)
  → /api/graphql (Apollo Server) → Resolver (auth + delegation) → Service (business logic) → Prisma → PostgreSQL
  → SyncAction created → Redis Pub/Sub → WebSocket server → all org clients
```

### Key Boundaries

- **`src/server/`** — backend only, never imported by client code. Contains GraphQL resolvers, services, middleware, and lib singletons.
- **`src/stores/`** — MobX observable entity pools. Components read from stores, not GraphQL queries.
- **`src/lib/`** — client-side utilities (sync-manager, transaction-queue, ws-client, Dexie DB).
- **`src/components/`** — React components, feature-grouped. `ui/` has shadcn/ui primitives.

### Data Flow (Client)

1. **Bootstrap:** `/api/sync/bootstrap` → IndexedDB (Dexie) → MobX stores
2. **Writes:** Optimistic MobX update → `TransactionQueue` enqueues GraphQL mutation → rollback on error
3. **Real-time:** WebSocket receives SyncActions → MobX stores updated → components re-render via `observer()`
4. **Delta sync:** `/api/sync/delta` catches up missed changes via `lastSyncId`

### Resolver → Service Pattern

Resolvers are thin: `requireAuth(ctx)` → `ctx.services.<domain>.method()` → return result with `lastSyncId`. All business logic lives in services. Services return plain objects, never GraphQL types. Error classes are internal to each service; resolvers catch and remap to `GraphQLError` with `extensions.code`.

### Prisma 7 Split Config

- **CLI** (`migrate`, `generate`): uses `prisma.config.ts` with `defineConfig({ datasource: { url } })`
- **Runtime**: uses `@prisma/adapter-pg` in `src/server/lib/prisma.ts`
- **Generated client**: `src/generated/prisma/` (gitignored — run `yarn db:generate` after checkout or schema changes)

## Key Conventions

### Database

- UUID PKs, soft delete via `archivedAt`, audit timestamps on all models
- snake_case DB columns (`@map`), timezone-aware datetimes (`@db.Timestamptz`)

### GraphQL

- Error discriminator: `extensions.code` (UNAUTHENTICATED, NOT_FOUND, INVALID_CODE, INVALID_TOKEN, FORBIDDEN, RATELIMITED, BAD_USER_INPUT)
- Mutations return `{ success, <entity>, lastSyncId }` — lastSyncId is a string (BIGSERIAL)
- SyncAction must be created for every mutation: `ctx.services.sync.createSyncAction(orgId, action, model, id, data)`

### MobX Stores

- Wrap components with `observer()` from `mobx-react-lite`
- Use `useStore()` hook (from StoreProvider context) to access RootStore — never import `getRootStore()` directly. No Redux/Zustand/React Query/SWR; use `useState` for ephemeral local UI state only.
- Use `store.pool.size` as dependency in `useMemo`, not the Map itself
- `TransactionQueue` instances share a singleton in-memory FIFO backed by an IndexedDB `pendingTransactions` table. `new TransactionQueue()` per component mount with `useMemo(() => new TransactionQueue(), [])` is still the convention — every instance enqueues into the shared queue. Pending transactions survive a page reload, scoped to the session that enqueued them (`orgId`/`userId` from the JWT). `SyncProvider` calls `TransactionQueue.setActiveSession(...)` then `TransactionQueue.hydrate(session)` once at app boot; rows from other sessions are deleted, not replayed.

### Auth

- Magic link email with 6-digit codes. Hash before store (`crypto.createHash('sha256')`). CSPRNG only (`crypto.randomInt`).
- JWT via `jose` (edge-compatible). Access tokens 24h, refresh tokens 30d in httpOnly cookies.
- `requireAuth(ctx)` uses TypeScript `asserts` narrowing.
- E2E test bypass: `NODE_ENV=test` + `TEST_AUTH_CODE=000000`

### Frontend

- TailwindCSS v4 + shadcn/ui only — no CSS Modules, no styled-components. Dark mode via `next-themes` (class-based).
- No hardcoded hex colors — use Tailwind semantic tokens or CSS custom properties (oklch theme tokens).
- Use `cn()` from `@/lib/utils` (clsx + tailwind-merge) for all class merging — never template-literal concatenation.
- Component files live in `src/components/<feature>/` — feature-grouped, kebab-case filenames. Interactive components are `'use client'`; pages and layouts are server components.
- Large client-only widgets use `dynamic(..., { ssr: false })` with a `.lazy.tsx` suffix (e.g. `tiptap-editor.lazy.tsx`, `issue-detail-panel.lazy.tsx`).
- Toast notifications: use `@/lib/toast` wrapper, never import sonner directly. It exposes `error/info/success/warning` plus `undo(message, label, onUndo)`, `loading`, `promise`, and `dismiss(id)`. `TransactionQueue` permanent failures with no per-call `onError` fall through to a default toast registered by `SyncProvider` — never rely on that as the primary UX for a known failure path.
- Logging: use `logger`/`childLogger` from `@/server/lib/logger` (pino). No `console.log` in server code.
- UI primitives in `src/components/ui/`: `Button` (CVA), `Badge` (CVA, variants: `pill`/`solid`), `UserAvatar`, `Select`, `Skeleton`, `SelectPopover`, `SearchableSelectPopover` (generic searchable dropdown — see `CycleSelect`/`ProjectSelect` for usage), `ModalDialog` (native `showModal()` — real focus trap; Escape arrives as the `cancel` event), `Input`, `Textarea`, `Switch`. Extend here, not inline — don't hand-roll form fields or toggles.
- Shared sub-components in `src/components/shared/`: `UpdateFormFields`, `DeleteUpdateButton`, `ConfirmDialog` (destructive confirmations — prefer over `window.confirm`). Add cross-feature building blocks here.
- Escape contract: whichever surface consumes an Escape must claim it (`preventDefault` + `stopPropagation` — `useOutsideClick` does this for popovers, capture-phase). Window-level Escape listeners on parent surfaces must ignore handled events (`if (e.defaultPrevented) return`). One Escape closes exactly one surface.
- Issue mutations from components: use `useIssueCreate(team, states)` and `useIssueUpdate()` from `src/hooks/` — they own the optimistic apply, TransactionQueue enqueue, rollback, and failure toast. Map store models for issue components with `toIssueUsers`/`toIssueLabels` from `@/lib/issue-mappers`; don't hand-roll the mapping.
- Issue creation UI: there is exactly one create modal — `GlobalCreateIssueModal`, mounted in `WorkspaceClient` and driven by `uiStore.openCreateIssueModal()`. Open it from buttons/shortcuts/palette actions via the store; never mount a second `CreateIssueModal`.
- Dropdown/popover state: use `usePopover({ open?, forceOpen?, onClose?, closeOnEscape? })` from `@/hooks/use-popover` — returns `{ open, setOpen, ref }`. `open` is fully controlled (parent owns show/hide); `forceOpen` is a one-shot uncontrolled open. For outside-click only (no popover state), use `useOutsideClick` from `@/hooks/use-outside-click` directly — it also takes an optional `closeOnEscape` param.

### Testing

- E2E tests (Playwright): `tests/e2e/`. Use `loginAs(page, email)` helper. Both dev server + WS server must be running.
